BUG: On the PRODUCTION site https://podlever.com, clicking "Start for free" (pricing page) redirects to Replit's OIDC login and returns the error "invalid_redirect_uri".

ROOT CAUSE (confirmed): The Replit Auth flow is sending this redirect_uri:
  https://3c6fd13e-8623-4039-a4c4-da7889e29cdb-00-34klxkjwr2nwp.worf.replit.dev/auth/callback
That is the DEVELOPMENT domain, not podlever.com. Replit's OIDC provider rejects it because podlever.com is not registered as an allowed callback domain, and the app is building the callback from the dev domain instead of the actual request host. (Confirmed separately: visiting https://podlever.com/auth/callback 302-redirects to the .replit.dev dev domain, proving the production build has the dev domain baked in.)

NOTE: My other deployed app pawsofkarma.com uses this same Replit Auth and works correctly end-to-end. Use its auth configuration as the known-good reference and make PodLever match it.

   (Include the dev domain too if the app still needs to run in preview, comma-separated.)

At login and callback time, select the strategy using the incoming request host (req.hostname), so the redirect_uri always matches the domain the user is actually on.
