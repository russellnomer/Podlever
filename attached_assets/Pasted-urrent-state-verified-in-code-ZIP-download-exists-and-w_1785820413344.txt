DR. ANANYA SHARMA — AI Product Architect
Readiness: 4/10 on writing quality specifically

The "11/10 writing" objective is achievable but requires architectural changes to the prompt system, not just better prompts. Here's the honest assessment:

Current state: Single-pass GPT call with a generic system prompt. Output quality is capped by the information the prompt has access to: the transcript, the episode metadata, and a generic instruction. No knowledge of the host's voice, the show's audience, the platform norms, or the communication style that resonates with that specific listenership.

What "11/10" requires:

Audience persona system. A defined library of audience archetypes — each with vocabulary profile, content preferences, attention span, platform behavior, and resonance triggers. At minimum:

The Executive (C-suite, time-scarce, ROI-driven, LinkedIn-native): lead with the takeaway, bullet-point everything, no fluff, strong data citations
The Creator (indie podcaster/YouTuber, peer-to-peer tone, Twitter/X native): casual authority, behind-the-scenes framing, actionable tactics, humor is welcome
The Wellness Seeker (lifestyle/health audience, Instagram native): aspirational framing, community language, sensory vocabulary, transformation arc
The Practitioner (B2B professional, newsletter reader): case study structure, mechanism-first, jargon is fine if precise, long-form tolerance high
The Fan (entertainment/true crime/sports): narrative hook, cliffhangers, character-driven, emotional peaks, Twitter/TikTok native
The Investor (VC/finance audience, Bloomberg/Twitter): signal density, no fluff, counterfactual framing, original insight valued above summary
Voice calibration. On first episode, extract stylistic fingerprints from the transcript: average sentence length, vocabulary complexity, humor markers, rhetorical devices. Feed this back as style guidance on every subsequent episode.

Platform-specific post formats. LinkedIn B2B carousel copy ≠ LinkedIn personal story post ≠ Twitter/X thread ≠ Instagram caption. Each has different hook structures, CTA patterns, and optimal lengths. These should be hardcoded as format templates filled by the LLM, not generated free-form.

Quality gate. Before returning content, run a secondary LLM pass that scores the output against the target audience profile and rewrites any section scoring below threshold. This is the "red team" mechanism built into the pipeline.

Defensibility note: This is the hardest thing for a competitor to copy quickly. Data-trained voice models are the moat. Every episode that runs makes the voice calibration better.

MARCUS REEVES — Seasoned CISO
Readiness: 5/10

Two security considerations for this agenda:

Logo upload: When you accept user-uploaded logos, you accept user-uploaded files. PNG/JPG uploads require validation (magic-byte verification, not just extension checking), file size limits, and server-side rendering (never execute uploaded content). If you're generating PDFs with user logos, the logo must be sanitized before insertion into the PDF generation pipeline. SVG uploads in particular are an XSS vector — accept only PNG/JPG/WebP.

Cross-promotion links: When linking to creatorvidpro.com, coveragecouncil.com, and russellnomermusic.com from within PodLever's authenticated session, ensure those links are rel="noopener noreferrer" and that you're not passing session tokens or user data across the domain boundary. Even within an owned portfolio, treat cross-domain links as external.
